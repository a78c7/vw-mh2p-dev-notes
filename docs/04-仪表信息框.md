# 04 仪表信息框

[← 目录](../README.md)

需求：原车仪表小窗口里的 G 值、功率只有动画没有数字，想在仪表上一眼看到功率、扭矩、G 值等实时数字。没有 OBD 编码工具，所以全部从车机侧做：在 CarPlay 仪表地图左侧叠一个半透明小框。

## 1. 数据从哪来

反编译 `lsd.jar`（方法见 [01 篇](01-调试环境与工具.md)）找到车机本来就能收到的 DSI 数据：

- `DSICarVehicleStates`
  - 属性 14 `DynamicVehicleInfoHighFrequent`：`currentOutputPower`（kW）、`currentTorque`（Nm）、`longitudinalAcceleration`（m/s²）、`lateralAcceleration`（**g**，原车 SportHmi 代码只把纵向除以 9.81 也印证了）、`engineSpeed`、`acceleratorPosition`（%）、`brakePressure`（≈ bar）、`wheelAngle`（方向盘角度 °）、`yawRate`（°/s）、四轮轮速、车速等。
  - 属性 12：上面各项的 ViewOptions（state 0 = 没有，1 = 装了但无效，2 = 可用）。
  - 属性 15（中频）：挡位、变速箱油温、kickdown、是否在刹车、ACC 等。
  - 属性 17（SemiStatic）：最大功率、最大扭矩、最大增压。
- `DSICarKombi`（行车电脑）：属性 64 机油温度、63 冷却液温度、6 当前消耗、23 油量百分比；"行驶数据"三个存储器——自启动起 = ShortTerm（属性 11 平均消耗、13 里程/车速/时间），自上次加油起 = Cycle（17、19），累计 = LongTerm（14、16）；三个 General 类结构相同（`CarBCDistance`、`CarBCSpeed`、`CarBCTime` 分钟）。

背景：大众车机本来有一个 Sport HMI 模块读功率/增压/G 值，但**国行皮肤（skin3）没有这个页面**，越野页只有指南针/海拔/温度/转向角。原车仪表上的 G 值小窗口动画是仪表自己画的，车机改不了。

## 2. 先做只读探针，实测本车

- 探针（Java，开关文件控制，只订阅不写）把回调记到日志。本车结果：功率、扭矩、加速度、转速、油门、刹车、方向盘角、横摆、轮速、车速都可用；四轮扭矩分配、四驱扭矩不可用；增压绝对值一直是 0（虽然标为可用）。**【MH2p 大众通用，具体可用项按车型】**
- 频率：着车后 8～10 次/秒，熄火约 3 次/秒。显示数字够用，做 G 值小球就得插值。
- 核对：1794 rpm、257 Nm → 算出 48.3 kW，车上报 48.0 kW，自洽。怠速 660 rpm 约 1.8 kW / 25 Nm。
- 单位：起步纵向 +3.2、刹车 −5.12（步长 0.16）是 m/s²；低速打满方向横向 ≈ −0.16，和横摆角速度 × 车速推算一致，是 g。
- 当前消耗的单位码会随行驶在 L/100km 和 L/h（停车时）之间切换。
- 油箱只给百分比，升数 = 百分比 × 油箱容积（途锐 90 L，可配置）。

## 3. 怎么画到仪表上

- 不改大众原生界面：在 `cl_render` 里画。面板在 CPU 上画进一个 RGBA pixmap，每帧视频 `screen_blit` 进 post buffer 之后再 `screen_blit` 一次面板，属性 `SCREEN_BLIT_TRANSPARENCY = SCREEN_TRANSPARENCY_SOURCE_OVER`（本车支持，半透明正常；不支持时代码自动退回不透明）。300 ms 没新视频帧时在最后一帧上补画。
- 中文：车机没有现成可用的字体库，干脆在编译时用 Noto Sans CJK SC 把要用的标签、数字、单位预渲染成 8 位覆盖度位图，运行时只做 alpha 混合。新二进制没有多出任何动态库导入。
- 数据通道：Java 插件只在 CarPlay 地图挂在仪表上时订阅 DSI，每 200 ms 写一行 `key=value` 到 `/tmp/dash.state`；`cl_render` 每 200 ms 读一次，5 秒没更新就隐藏。屏幕上数字最多每秒变 5 次。
- G 值：合成值 `sqrt((纵向/9.81)² + 横向²)`，0.5 指数平滑（滞后约 0.2～0.3 秒）；正负号取纵向分量（加速 +、刹车 −），只转弯时不带符号——横向的左右用正负号表达不直观。

## 4. 坑：车机 /tmp 不能改名

- 第一版 Java 写临时文件再 `renameTo`（避免读到半行），结果框一直不出来：车机 `/tmp` 不支持 rename / link，数据全留在 `.new` 里。改为直接覆盖写一整行，读端只用以换行结尾的完整行。**【MH2p 通用】**

## 5. 位置和内容的取舍

- 实拍照片量出：仪表自己的导航条（剩余距离/路名/到达时间）盖住窗口最上面约 160 行，左下角挡位框从约 510～520 行开始，所以框最初放在 y=172。后来按照片精确对齐，见第 11 节。**【途锐特有】**
- 默认 6 行：功率、扭矩、G 值、转速、机油温度、变速箱油温。挡位、油量/续航仪表本身就有；冷却液热车后一直 90°C 没信息量，换成转速（两侧表盘隐藏后看不到转速）。
- 仪表顶部那条导航条是仪表自己画的，透明度改不了。

## 6. 可自定义（v17）

- 配置文件 `dash.conf` 的 `items=` 决定显示哪几项、什么顺序，最多 10 项。框的宽高按所选项计算；字号三档：1～6 项大字（行高 52）、7～8 项中字（40）、9～10 项小字（32），三档都不会盖到挡位框。
- 名称按大众说明书：当前消耗、续驶里程、车外温度、机油温度、冷却液温度、燃油存量、制动压力、转向角，以及三个存储器各自的平均消耗、行驶里程、平均车速、行驶时间（框里分两行，上面小字是存储器名）。
- 行车电脑三个存储器的读数已上车核对，和原车"行驶数据"页一致。

## 7. 0–100 计时

- 在 Java 的高频回调（8～10 次/秒）里算，不放在 `cl_render` 里（它每 200 ms 才读一次数据，精度不够）。
- 用 `realVehicleSpeed`（真实车速，结构同 `CarBCSpeed`，桩类里没有，靠反射读），不用表显车速：表显车速一般比真实高几个百分点。**【MH2p 大众通用，字段名以反射日志为准】**
- 状态机：车速 < 0.5 km/h 时"上膛"；越过 0.5 km/h 开始，越过 100 km/h 结束，两个时刻都在前后两个采样之间线性插值，所以精度不受 0.1 秒的采样间隔限制。中途车速比本次最高点低 3 km/h（松油门/刹车）或超过 30 秒就作废。
- 坑：轮速信号在极低速时一直读 0，起步后第一个非零采样已经是好几 km/h，直接取 0.5 km/h 的插值点会把起步算晚。解决：拿起步后前两个非零采样**外推回 0 km/h** 当起点，并限制在"最后一个读 0 的采样往前 1 秒"到"第一个非零采样"之间。用模拟数据测，修正前偏差约 0.09 秒，修正后和真值一致。
- 显示：起步后实时显示已用秒数，过 100 显示成绩并保留到下一次。

## 8. 最大值和扭矩的口径（实测）

- "最大功率 / 最大扭矩 / 最大 G 值"从车机开机算起，熄火关机就清零。加了合理范围（功率 < 600 kW、扭矩 < 1500 Nm、G < 2.5），防止一个坏采样一直挂在最大值上。
- 发动机上**没有扭矩传感器**，`currentTorque` 是发动机 ECU 用进气量、点火角、喷油量等估算的，经网关转给车机。车机报的功率就是 ECU 用同一个扭矩算的：行车记录里每一行都满足 **功率 = 扭矩 × 转速 ÷ 9549**（误差 1 kW 以内）。
- 途锐 3.0T 实测：油门 68% 加速时，2700～3800 rpm 扭矩稳定在 450～460 Nm、持续约 3 秒，比额定 450 Nm 略高。车自己在 SemiStatic 数据里报的最大扭矩也是 450。**【途锐特有】**
- 口径：厂家公布的功率扭矩按国标（GB/T 17692）在发动机台架上测，是曲轴端，没扣变速箱损失；车机报的扭矩和它同一端，可以直接比。底盘测功机测的是轮上，低 15%～20% 很正常。略高于额定的原因可能是估算误差、短时超增压或"内部扭矩"口径（没扣摩擦损失），接口里没写，要靠大油门记录判断。

## 9. 行车记录到 U 盘

- 想把高频数据全部记下来分析，但插件进程不一定有 U 盘写权限，U 盘也可能是只读挂载。所以分两段：
  1. Java 把每个高频回调记一行 CSV，每 10 秒写一个分块 `/tmp/drv_<会话>_<序号>.csv`。**先**把"正在写哪个分块"写进 `/tmp/drv_cur`，再创建分块，搬运方就不会拿走还在写的文件。
  2. 开机脚本（ModKit 的 Persist，root）每 5 秒把写完的分块 `mount -uw` 后追加到 U 盘 `drive_logs/drive_<会话>.csv`，成功再删 `/tmp` 里的分块。
- 开关就是 U 盘根目录有没有 `drive_logs` 文件夹（脚本建一个 `/tmp/vwcn_log_on` 告诉 Java）。U 盘上不能有 `Data`、`Meta`，否则一插就进入 ModKit 刷机。
- `/tmp` 是内存：最多积压 60 个分块，再多就丢数据并记一次日志。熄火时最后不到 10 秒可能没存上。
- 时钟从 1970 开始（见 01 篇第 8 节），会话名会重复：每次开机第一个分块挑一个 U 盘上还没有的文件名，记在 `/tmp/drv_map_<会话>` 里，同一次开机后面的分块都追加到它。
- 约 10 行/秒，每小时约 5 MB。挡位字段目前读得不对（行驶中一直是 0/1），待查。

## 10. 左右两个框

- 原来的绘制代码是一组全局变量（配置、项目列表、字体、尺寸、像素缓冲）。改成两个框结构体，`dash_use(i)` 把第 i 个框换进全局变量，原来的排版和绘制函数一行不改。
- 配置里 `r_` 开头的键属于右边框（`r_items`、`r_show`、`r_x`、`r_y`、`r_right`），油箱容积、横向 G 方向、透明度两个框共用。
- 两个框都显示时：先各自排版，取较小的字号再统一排一次，再把高度都设成较高的那个（项目少的框下面留空），看起来左右对称。
- `cl_render` 给每个框一个 pixmap，每帧各自 `screen_blit`（SOURCE_OVER）到仪表画面上。

## 11. 用照片对齐位置

- `dmdt ts 4` 截不到仪表自己画的导航条、挡位框、车速框（01 篇第 4 节），只能拍照：在照片上找已知坐标的参照（截图里能看到的地图元素和照片对上），算出比例和偏移，再量导航条底边（途锐约 y=156）、挡位框顶边（约 509）和挡位框斜角的位置（约 x=300）。**【途锐特有】**
- 改成"给定右边缘"：配置 `right=` 指定框的右边缘，宽度固定后先收紧左右留白和列间距，还放不下再换小一号字体（增加了一档 36 px）。途锐最后用 `x=5, y=164, right=300`：右边缘对齐挡位框斜角，上下留白相近。
- 右边框按画面左右对称放在 1620～1915，还要拍照核对车速框的斜角。

## 12. 其它

- 换 `cl_render` 不用重启车机：`slay cl_render`，`clusterd` 会立刻用新程序重新拉起；Java 插件改了才要重启车机。
- 插件切仪表显示失败时重试间隔不要太短、日志只记一次，否则日志很快写满被清空。
