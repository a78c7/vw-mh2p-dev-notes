# R4 显示系统

[← 平台参考](README.md)

## 1. 屏幕编号

displaymanager 的配置（`displaymanager.json`）里的编号：

| 编号 | 屏 | 接口 | 尺寸 | 范围 |
| --- | --- | --- | --- | --- |
| 0 | 中控屏 | LVDS1 / HDMI1 | 1920×1020 | 【途锐实测】 |
| 4 | 仪表 | LVDS2 / INTERNAL2 | 1920×722 | 【途锐实测】 |
| 5 | HUD | MOST | — | 【途锐实测】 |

- QNX 的 `/dev/screen/0` 下能看到两块物理屏（dpy-1 中控、dpy-2 仪表）。【途锐实测】
- CarPlay 主屏协商的分辨率是 1540×720（物理 235×110 mm）。【途锐实测】
- **HUD 不是视频**：车机不给 HUD 发画面，只通过 BAP 发箭头、距离、路名等数据，由 HUD 自己画（见 [R2](R2-HMI-J9-Java.md) 第 7 节）。【途锐实测】

## 2. displayable（窗口）编号

每个要显示到某块屏上的 QNX screen 窗口都有一个编号（窗口的 ID 字符串），displaymanager 按编号决定每块屏显示哪些窗口。

| 编号 | 是什么 | 范围 |
| --- | --- | --- |
| 33 | 原车导航的**仪表地图**窗口，1920×639，RGBA8888，GLES2 画。窗口状态显示 INVISIBLE，但内容照样合成到仪表上 | 【途锐实测】。保时捷 PCM 5 上也是 33（来自 fifthBro 的资料） |
| 58 | `DISPLAYABLE_GOOGLE_EARTH_KOMBI_MAP_VIEW`，谷歌地球仪表地图，国内用不到，可以拿来放自己的画面 | 【途锐实测】 |
| 19、22、23、60、103、104 | 导航进程拥有的其它窗口，其中某个是中控屏地图区 | 【未验证：各自是什么没查】 |

规则（都是【途锐实测】）：

- **同一编号绑定到最后创建的那个窗口。**自己的窗口也叫 33 时，原车的 33 会被挤掉；自己的退出后原车的不会重新绑定，仪表就卡在最后一帧。
- 显示列表里**第一个在最上层**。仪表设成 `[58, 33]`：自己的画面在上面，原车的 33 垫在下面"在场"。只放自己的编号时，仪表会报"加载失败"。
- 仪表的显示列表会被原车切换覆盖，要定期重申（途锐用每 3 秒一次）。

## 3. 仪表上谁画什么

仪表画面分两部分：

- **车机发过去的画面**：窗口 33（或你放上去的窗口）。
- **仪表自己画的**：顶部导航条（剩余距离、路名、到达时间）、时钟、挡位框、车速框、指针、警告灯、提示框。这些车机改不了，`dmdt ts 4` 也截不到，要定位只能拍照。【途锐实测】

途锐上量出来的位置（以 1920 宽的仪表画面为准，【途锐特有】）：

| 元素 | 位置 |
| --- | --- |
| 顶部导航条底边 | 约 y = 156 |
| 时钟中心 | 约 x = 965（不是画面中心 960） |
| 左下挡位框顶边 | 约 y = 509 |
| 挡位框右上斜角 | 约 x = 300 |

拍照定位的方法：在**同一张照片**里找已知坐标的参照（截图里能看到的地图元素），算出比例和偏移再换算。用不同照片估的数互相会对不上。

两侧表盘可以在仪表设置里隐藏，地图就铺满整个画面。【途锐实测】

### 自己的窗口偶尔不显示

开机后、或者 CarPlay 重连后，偶尔出现：显示列表明明是 `[58, 33]`，`dmdt ts 4` 截到的却是原车地图（自己的画面没出来）。把自己的显示程序杀掉重开就好了，原因没找到。途锐的做法是每次连上后 20 秒重启一次显示程序（画面闪一下）。【途锐实测】

## 4. 画到屏上的方法

| 项 | 结论 | 范围 |
| --- | --- | --- |
| H.264 解码 | NvMedia 硬解可用 | 【途锐实测】 |
| YUV 转 RGB | NvMedia Mixer 在途锐上直接返回错误（不工作），改用 `screen_blit` 做转换 | 【途锐实测】 |
| 半透明叠加 | `screen_blit` 设 `SCREEN_BLIT_TRANSPARENCY = SCREEN_TRANSPARENCY_SOURCE_OVER` 可用 | 【途锐实测】 |
| 中文字 | 车机没有可直接用的字体库，编译时预渲染成位图，运行时只做 alpha 混合 | 【途锐实测】 |
| 截物理屏 | `screen_read_display`（显示管理权限的 context）能抓中控和仪表的实际输出 | 【途锐实测】 |

## 5. dmdt（车机自带的显示调试工具）

`/eso/bin/apps/dmdt`。【MH2p 通用】

- 要在一个有 `./config -> /etc/eso/production` 的目录里运行，而且要终端（`ssh -tt`），否则没有输出。
- `LD_LIBRARY_PATH=/mnt/app/armle/lib:/mnt/app/armle/usr/lib:/mnt/app/armle/graphics:/eso/lib:/lib:/usr/lib`

| 命令 | 作用 |
| --- | --- |
| `dmdt gd` | 列出所有 displayable |
| `dmdt gs` | 每块屏当前显示哪些 |
| `dmdt sd 4 58 33` | 设置仪表（屏 4）的显示列表 |
| `dmdt ts 4 /tmp/a.png` | 截取车机发给仪表的画面。命令返回后文件还在写，等 2～3 秒再取 |

## 6. 换车型先查什么

1. `dmdt gd` / `dmdt gs`：仪表是哪个屏编号、原车仪表地图是哪个 displayable、有哪些空闲编号。
2. 原车有没有"仪表显示导航地图"的功能。途锐的方案是借用原车地图的位置；原车没有这个位置，就得另找办法。
3. 拍照量出仪表自己画的元素的位置。
